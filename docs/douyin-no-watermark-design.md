# 抖音分享链接无水印下载功能设计

## 1. 产品目标

在现有 Bili23-Downloader 中增加一个独立的抖音下载适配器：用户把抖音分享链接粘贴到现有解析输入框，程序识别链接、获取公开视频详情，选择公开接口提供的无水印播放地址，并复用现有下载队列、断点续传、命名和任务历史能力。

这项功能只处理用户有权保存的公开内容，不绕过登录、付费、隐私或其他访问控制，也不做批量抓取和账号风控规避。

核心要求：正常下载流程不要求用户登录抖音账号，不读取或保存抖音 Cookie，不弹出账号登录、短信验证或扫码登录界面。

## 2. 用户流程

1. 用户粘贴抖音长链接或 `v.douyin.com` 分享短链接。
2. 现有“解析”按钮和剪贴板监控识别链接来源。
3. 解析列表展示：标题、作者、封面、时长和来源标识“抖音”。
4. 用户勾选条目并点击现有“下载选中项”。
5. 下载任务沿用现有队列、进度、暂停、取消、断点续传、文件命名和下载历史。
6. 输出为包含音视频的 MP4 文件；抖音专属的弹幕、字幕和 B 站账号能力不对该条目显示或执行。

## 3. 范围边界

### 本期包含

- 抖音公开分享链接识别和短链解析。
- 无需抖音账号登录即可解析和下载可公开访问的视频。
- 单个公开视频详情解析。
- 公开接口返回的无水印视频地址选择。
- 复用现有下载任务和下载器，支持重试、Range 分片和断点续传。
- 解析失败、链接失效、需要登录和服务端限流的明确提示。
- 单元测试、接口响应 fixture 测试和现有验证流程。

### 本期不包含

- 抖音登录、Cookie 收集或账号操作。
- 私密视频、付费内容、年龄/地区限制和其他访问控制的绕过。
- 批量账号抓取、作者空间、合集和搜索接口。
- 改动现有 B 站解析协议和 UI 工作流。
- 自动发布、转码或向第三方上传视频。

## 4. 技术方案

### 4.1 Provider 适配层

新增 `src/util/douyin/`，集中放置抖音协议相关代码：

- URL 识别、短链解析和视频 ID 提取。
- 短链解析和浏览器捕获结果归一化。
- 在桌面 GUI 中使用独立的、仅驻留内存的 Qt WebEngine profile 加载公开 PC 详情页，让页面自身执行正常的 JavaScript。
- 捕获页面公开响应 JSON；字段查找采用递归遍历，不依赖单一固定 JSON 路径。
- 无水印地址选择策略：优先 `play_addr` / `play_addr_h264`，`download_addr` 仅作为兼容性兜底；只做公开 URL 的规范化，不生成签名、不绕过访问限制。
- 浏览器只负责解析和提供临时媒体地址，媒体字节仍由现有下载器请求，不调用抖音网页的下载动作。

B 站模块不调用该适配层，保证来源逻辑隔离。

### 4.2 现有解析管线接入

在现有 URL pattern 和 `ParseWorker` 中增加 `douyin` 分支，生成标准 `TreeItem`。解析结果通过 `EpisodeData` 携带 provider、视频 ID、临时媒体地址、请求头和媒体尺寸等最小元数据。

任务模型增加可选的跨平台媒体字段，旧任务缺少这些字段时继续按 B 站默认逻辑运行。抖音条目使用独立的 provider 分支，不读取 `bvid`、`cid` 或 B 站播放接口。

### 4.3 预览与下载

- 预览阶段展示单一 MP4 视频质量，不显示 B 站清晰度、编码、音轨和弹幕选项。
- 下载解析阶段根据抖音视频 ID 重新打开公开页面并获取最新媒体地址，避免长期任务使用已过期直链。
- 下载会话使用页面来源所需的 Referer/User-Agent，不向抖音发送 B 站 Cookie，也不保存浏览器 profile。
- 下载结果走现有分片下载器；若响应不支持 Range，则明确降级为单流下载或提示失败，不能伪造分片状态。
- 抖音视频通常已包含音频，因此本期按单个视频文件处理，不进入 B 站 DASH 音视频合并流程。

## 5. 数据与错误处理

所有新增字段均为可选字段，并为旧数据提供默认值。媒体直链视为短期缓存，不作为永久下载凭证保存；任务恢复时优先用视频 ID重新解析。

错误提示至少区分：

- 无法识别分享链接。
- 短链无法解析或视频 ID 缺失。
- 公开详情接口未返回视频。
- 内容需要登录、不可访问或已失效。
- 没有可用的公开媒体地址。
- 下载地址过期、限流或不支持断点续传。

如果公开接口明确返回登录要求、权限不足或内容不可访问，程序直接给出说明并停止该任务；不尝试通过账号凭据、验证码、签名伪造或其他方式绕过限制。

日志中不得输出 Cookie、完整带签名的媒体 URL 或其他敏感请求数据。

## 6. 测试和验收标准

- URL 测试覆盖长链接、短链接、带查询参数链接、无效链接。
- 响应 fixture 覆盖下载地址、播放地址、字段缺失、错误响应和过期响应。
- 验证无水印地址选择只使用公开响应字段，并正确处理 URL 规范化。
- 验证嵌套响应可以递归找到详情，且 `play_addr` 优先于 `download_addr`。
- 解析器测试确认 B 站输入仍走原有 parser，抖音输入才走 Douyin parser。
- 下载任务测试确认抖音任务不调用 B 站播放接口、不发送 B 站 Cookie，并能恢复旧任务。
- 运行项目现有测试、Python 编译检查和 `git diff --check`。
- 每一个实现阶段都单独提交 Git commit，提交前工作区必须可验证、可回滚。

## 7. 分阶段交付

1. 适配层和 URL/响应 fixture。
2. 解析列表和任务模型接入。
3. 预览、下载和任务恢复接入。
4. GUI 文案、错误提示和使用说明。
5. 全量测试、手工验证和最终提交。
